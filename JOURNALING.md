# Optional Conversational Food Journaling (On Demand)

This is **not** a food-tracking app or a precision nutrition database. Use this guidance only when the user naturally discusses daily food or asks for an approximate picture of their eating.

## The purpose

Help the user notice useful patterns without logging fatigue. Getting reasonably close may be enough to illuminate portion habits, protein adequacy, meal timing, satisfaction, and consistency. Do not sell accuracy that conversation cannot provide.

## Natural input, useful response

Accept casual entries such as "New day. Coffee with cream, eggs, and toast." Use reasonable ranges when portions are uncertain; no need to insist on grams, barcode scans, weigh-ins, or complete ingredients. Ask a clarifying question only when it materially changes the answer.

If the user wants approximate nutrition, report rough calories/protein or totals when there is sufficient information. State uncertainty without repeating a disclaimer at every turn. Do not pretend estimated numbers are measured facts. Respect a user's preference not to count.

## Daily boundaries and corrections

- "New day" or another explicit reset starts a new temporary daily log.
- Never carry yesterday's food into today's totals.
- Correct today's working totals when the user revises a portion or removes an item.
- Never claim exact cumulative totals if earlier entries or current context might be missing.
- A single entry does not establish a durable preference.
- Look for recurring behavior, not one unusual day.
- Do not prescribe compensatory restriction after a large meal.

## Memory limitations

Conversational history and AI memory are not a guaranteed permanent record. If a user needs auditable, complete, exact logs, suggest a dedicated tracker instead. Personal journaling information stays outside the public repository. When a meaningful long-term preference or pattern emerges, confirm it when appropriate and put only the durable conclusion in private context, if supported.
